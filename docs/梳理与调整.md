# 页面、题目与答案梳理（2026-10-21）

对照用人画像（专业 / 表达 / 应变：能讲清楚、能应变、能自己想新问题）逐项检查。✅ 保留，🔧 已调整，⚠️ 仍需留意。

## 一、页面布局

| 项 | 结论 | 说明 |
|---|---|---|
| 单一入口 `index.html` | ✅ | 通用题池、简历板块、评估方法三个视图，离线可用，简历加密 |
| 侧栏 27 个分类平铺 | 🔧 | 归为 7 组：架构与编排 · 模型与生成 · 检索与知识 · 工程与可靠性 · 质量与交付 · 业务场景 · 现场与表达；空分类自动隐藏 |
| 顶栏按钮多、两行筛选 | 🔧 | 顶栏只留搜索和「面试模式 / 随机 / 打印 / 下载」；筛选合并为一行：维度分段（全部/专业/表达/应变）+ 题单 / 未问 / 只看问题 |
| 题卡信息一次铺开 | 🔧 | 默认只显示问题；展开后依次是参考要点 → 「深挖追问 ｜ 情景变更」 → 「高分信号 ｜ 风险信号」并排两栏 |
| 简历板块：画像和核实点压在题目上方 | 🔧 | 板块内第一个标签「概览」放画像、核实点、策略、打分；题目在「全部题目」和各分块标签里 |
| 题号 `C-p2-3` 不直观 | 🔧 | 统一显示「C · 项目2 · 第3题」，侧栏、标签、标题用同一套项目编号 |
| 现场提问时信息太多 | 🔧 | 新增「面试模式」：全屏一次一题，←/→ 切换，空格显示要点，A 标记已问，Esc 退出 |
| 风格 | 🔧 | 白底、单一深色主色、大标题、宽留白；三个维度各用一个低饱和色 |
| 手机端 | 🔧 | 侧栏收起为下拉；简历板块内用横向标签切换分块，当前标签自动滚入视野 |

## 二、题目

| 项 | 结论 | 说明 |
|---|---|---|
| 维度标签 | 🔧 | 原来 342/400 题都标「专业+应变」，筛选没有区分度。现在每题只标一个主维度：专业 351 · 应变 34 · 表达 15。通用题以技术深度为主是合理的，表达和应变主要靠简历板块（表达 44 · 应变 44）、「项目表达与情景应变」分类，以及每题都有的「情景变更」来考 |
| 「补充深度场景与追问」 | 🔧 | 杂项分类，21 题全部归入对应主题（工具安全、记忆、多智能体等），分类隐藏 |
| 题目长度 | 🔧 | 通用题 21 道超过 60 字，已精简到 55 字内；简历题 28 道超过 75 字，已精简到 70 字内，细节移入要点或追问，现场可一口气读完 |
| 重复题 | ✅ | 文本相似度检查无重复；相近的是「概念题 ↔ 对应编程题」（如幂等设计 ↔ 幂等包装器实现），属于递进，保留 |
| 旅游行业题 | ⚠️ | 44 道题以旅游场景为背景（原题库定位）。候选人多来自电商、汽车、物流，提问时可把场景换成对方熟悉的行业，考点不变 |
| 知识图谱、多模态 | ⚠️ | 各约 5~6 题，偏少；后续简历沉淀会继续补充 |
| 简历题与简历一致性 | ✅ | 4 个板块已逐题对照简历复核：去掉简历未写的数字和假设，修正少量技术表述，核实点改为中性语气 |
| 块内顺序 | ✅ | 表达 → 专业 → 应变，三种维度每块都有 |

## 三、答案摘要

| 项 | 结论 | 说明 |
|---|---|---|
| 参考要点 3 条 | ✅ | 每条 ≤ 70 字，写“好回答应覆盖什么”，不是标准答案全文 |
| 简历题的要点 | ✅ | 标题为「好回答应覆盖」，因为真实答案只有候选人知道 |
| 深挖追问 / 情景变更 | ✅ | 每道通用题都有情景变更，任何专业题都能现场转成应变题 |
| 高分 / 风险信号 | ✅ | 写成可观察的行为，便于现场判分 |
| 展示方式 | 🔧 | 由竖排六段改为「要点 + 两栏对照」，并在面试模式中可一键显示 |
