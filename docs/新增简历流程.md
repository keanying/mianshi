# 新增简历流程

简历会持续加入。每份简历是一个**独立板块**，互不影响；已有板块的题目、已问记录和打分都不会因为新增简历而改变。

## 步骤

1. **分配编号**：按收到顺序取下一个字母（A、B、C、D 之后是 E、F…，超过 Z 用 AA、AB…）。编号一经分配不再变更，本机的已问记录和打分按编号保存。
2. **转录原文**：写入 `private/resumes/<编号>/resume.md`，保留简历原有分块（专业技能 / 工作经历 / 每个项目），末尾附「观察到的核实点」。截图分辨率低时先放大分段识别，拿不准的名称标注“（待核对）”。
3. **出板块题**：按 `docs/题目规范.md` 和 `docs/简历板块规范.md` 生成 `private/resumes/<编号>/questions.json`：
   - 每个分块一组题，块内按「表达 → 专业 → 应变」排列，三种维度都要有；
   - 题目 id 以编号开头（如 `E-p2-3`），全局唯一；
   - 时间线、数字口径、前后矛盾等放进 `verify`。
4. **沉淀通用题**：从本份简历的 `poolCandidates` 中，去掉与通用题池已有题（含之前简历沉淀的题）重复或高度相近的，其余追加到 `data/pool/added.json`，保留 `origin.block` / `origin.question` 指向来源题。只追加，不改动已有题的顺序，避免题号变化。
5. **构建与检查**：
   ```bash
   python3 scripts/build.py           # 全部板块 + dist/candidates/<编号>.html
   python3 scripts/build.py --public  # 公开版，只含通用题池
   node scripts/check_ui.js           # 浏览器检查：总览、板块分块、直达链接、单独文件、手机布局
   ```
   构建脚本会检查编号与目录一致、题目 id 唯一、每块是否覆盖三种维度。
6. **提交**：只提交 `data/pool/added.json` 与公开版构建产物。`private/` 和含简历的构建产物已被 `.gitignore` 排除，不要强制提交到公开仓库。

## 产物

| 文件 | 内容 | 用途 |
|---|---|---|
| `dist/interview-workbench.html` | 通用题池 + 全部简历板块 + 评估方法 | 面试官本人使用 |
| `dist/candidates/<编号>.html` | 通用题池 + 该份简历的板块 | 转给负责这位候选人的其他面试官 |
| `dist/interview-workbench-public.html` | 只有通用题池与评估方法 | 可公开 |

页面地址带 `#/resume/<编号>/<分块 id>` 时会直接打开对应板块和分块，可以收藏或发给同事（同一文件内有效）。
