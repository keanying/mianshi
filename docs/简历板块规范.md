# 简历专项题目规范

先读通用规范 docs/题目规范.md。本任务：针对一份简历，按简历分块（专业技能 / 工作经历 / 每个项目各一块）出“简历专项题”，并把其中有通用价值的题去个人化后沉淀到通用题池。

## 分块与出题要求
- 每个块：`excerpt` 用 ≤ 160 字概括该块简历原文的关键信息（技术栈、声称的数字），方便面试官边看边问。
- 每个块的题目数：内容丰富的核心项目 7~9 题；内容较薄或年代较早/与岗位关联弱的项目 3~4 题；专业技能块 4~6 题；工作经历块 3~5 题。
- 每个块必须同时覆盖三种维度，并大致按面试顺序排列：
  1. `exp` 表达题打头：让候选人在限定时间内讲清楚（如“用 2 分钟讲清楚……的数据流/你个人负责哪段”“这个 93% 的口径和基线是什么”），考察结构化、数据口径、个人贡献边界。
  2. `pro` 专业深挖题：围绕简历写到的具体技术点追问原理和取舍（为什么这样设计、替代方案、失败模式）。必须引用简历里的具体细节，不要泛泛而问。
  3. `ext` 扩展/应变题：在该项目基础上改变条件或提出新需求（数据量×100、换模型、增加权限、某依赖挂了、业务方改口径、要上线到新场景……），看候选人能否重新推导并说清楚为什么。
- 每题字段：`id`（如 "A-p2-3"）、`dim`（pro/exp/ext 单值）、`question`（≤ 110 字）、`points`（3 条“好回答应覆盖的要点”，每条 ≤ 70 字）、`follow`（≤ 40 字追问）、`twist`（可选，≤ 80 字，ext 题可省略）、`good`（高分信号 ≤ 60 字）、`bad`（风险信号 ≤ 60 字）。
- 要求“针对简历中的内容扩展”：大量使用简历里的具体名词、数字和设计（例如“rerankMinScore=0.4 怎么定的”“9 节点合并为 7 节点后失去了什么”）。
- 核实类问题（时间线、数字口径、个人贡献、简历前后矛盾）放进 `verify` 列表而不是题目里，但每个块里的 exp 题可以顺带核实数字。语气中立，不做人身判断。

## 输出 JSON 结构
```json
{
  "id": "A",
  "label": "候选人 A",
  "source": "第 1 份简历",
  "receivedAt": "2026-10-20",
  "headline": "≤ 30 字的方向概括",
  "profile": "≤ 120 字画像：经历背景、技术主线、亮点、疑点",
  "focus": ["面试策略建议 3~4 条，每条 ≤ 60 字，结合三个维度说明重点考什么"],
  "verify": [{"point": "≤ 60 字核实点", "ask": "≤ 60 字建议问法"}],
  "blocks": [
    {"id": "A-skill", "name": "专业技能", "kind": "skills", "period": "", "excerpt": "...", "questions": [ ... ]},
    {"id": "A-work1", "name": "公司 · 岗位", "kind": "work", "period": "2020.08-2026.02", "excerpt": "...", "questions": [ ... ]},
    {"id": "A-p1", "name": "项目名", "kind": "project", "period": "2026.03-2026.08", "excerpt": "...", "questions": [ ... ]}
  ],
  "poolCandidates": [
    {"category": 23, "question": "...", "points": ["...","...","..."], "follow": "...", "dims": ["pro","ext"], "good": "...", "bad": "...", "twist": "...", "fromBlock": "A-p1", "fromQuestion": "A-p1-4"}
  ]
}
```
- 简历没有写工作经历段落的（如只有项目），可以省略 work 块；没有项目时间的 period 留空。
- `poolCandidates`：10~16 道。从本简历题中挑出“换一个候选人也值得问”的题，去掉人名、公司名、简历特有数字，改写为通用题（仍保持具体场景），使用 题目规范中的分类下标（可以用新增的 23~26）。必须有 `twist`。不要与通用题池已有题目重复——已有题目见 dist/interview-workbench-public.html 或 data/pool/，重复或高度相近的不要提。
- 只输出合法 JSON，用 python3 json.load 自检，并检查每个块三种 dim 都存在、题目 id 唯一。
