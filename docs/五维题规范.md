# 五维题规范

面试评估统一用五个维度，每项 0~5 分：

| 代码 | 维度 | 看什么 | 典型问法 |
|---|---|---|---|
| `pro` | 专业度 | 做过的事是否真懂：原理、取舍、踩过的坑 | 「那个召回率从 70% 到 90%，具体是改了哪一步？」 |
| `drive` | 自驱力 | 主动找事做、主动学、主动推动，而不是等安排 | 「这个项目是你提出来要做的，还是领导安排的？」 |
| `trait` | 性格特质 | 沟通、合作、抗压、面对分歧和批评时的反应、是否坦诚 | 「上次被人当面指出方案有问题，你当时怎么回的？」 |
| `logic` | 逻辑思维 | 先结论后原因、有条理，数字和因果对得上 | 「用三句话说清楚：这个系统解决了谁的什么问题，效果怎么量的？」 |
| `adapt` | 适应力 | 条件变了、遇到没见过的问题，能不能想出办法并说清为什么 | 「要是明天模型供应商停服，你的系统先改哪里？」 |

旧的三维标签按下面对应：专业 `pro` → 专业度，表达 `exp` → 逻辑思维，应变 `ext` → 适应力。

## 简历板块里的「五维题」

每份简历一组，每个维度 6~10 道（简历素材多的维度多出，素材少的不少于 6 道），共 30~50 道，存在该简历 `questions.json` 的 `blocks` 里，排在所有简历分块之后：

```json
{"id": "C-d-pro", "name": "专业度", "short": "专业度", "kind": "dim", "dim": "pro", "excerpt": "这一维度要重点看什么（结合这份简历，一两句）", "questions": [
  {"id": "C-d-pro-1", "dim": "pro", "question": "…", "points": ["…", "…", "…"], "follow": "…", "good": "…", "bad": "…"}
]}
```

五个块的 id 依次为 `<编号>-d-pro`、`-d-drive`、`-d-trait`、`-d-logic`、`-d-adapt`。

## 出题要求

1. **大白话**：像当面聊天那样问，一句话问一件事，不超过 50 个字。不用「请阐述」「谈谈你对……的理解」「如何保证……性」这类书面腔。
2. **贴着简历问**：尽量点名简历里的项目、数字、做法。自驱力、性格特质也要落到具体经历上（「做 XX 项目的时候……」），通用问法每个维度最多 1 道。
3. **要例子**：自驱力、性格特质题要求候选人讲真实发生过的事，而不是问「你觉得自己……吗」。
4. **不和已有简历分块题重复**：专业度、适应力题换一个角度问，不要照搬分块里已有的题。
5. 每题字段：`points` 3 条「好回答应该提到什么」（每条 ≤ 50 字），`follow` 追问一句（≤ 30 字），`good` 听到什么说明不错、`bad` 听到什么要警惕（各 ≤ 40 字），都用大白话。
6. 不评判人格、不涉及婚育、年龄、籍贯等与岗位无关的话题。
