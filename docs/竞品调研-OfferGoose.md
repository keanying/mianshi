# 竞品调研：OfferGoose 鹅来面（原「多面鹅」）

> 调研日期：2026-10-21。官网 offergoose.cn 在本环境无法直接访问，以下来自官网搜索摘要、App Store 页面和第三方测评。第三方测评多为推广文，其中的“通过率提升 xx%”之类数字不可信，只采信功能描述。「实现」部分是根据公开描述做的推断，已标明。

## 一、它是什么

**面向求职者（候选人）** 的 AI 面试工具，和我们正好站在桌子两边：我们帮面试官问得准、评得准，它帮候选人练习和“现场提词”。

| 功能 | 公开描述 | 说明 |
|---|---|---|
| AI 模拟面试 | 根据简历和目标岗位出题，AI 面试官会针对回答追问，结束后给反馈和改进建议 | 第三方称覆盖 1000+ 岗位、2000+ 题库，并有“压力面试”模式、表达流畅度 / 逻辑结构等维度评分 |
| 简历优化 | 官网定位之一 | — |
| **面试实时助手** | “通过捕捉系统音频，识别面试内容，理论支持所有平台”；“无论是视频面试还是电话面试，AI 都能精准听取并识别面试官提问，并结合你的简历与 JD，现场生成高分回答思路与金句” | 第三方实测：约 1 秒出回答思路、约 20 秒出深度分析；支持中英文；对网络稳定性要求高 |
| 平台 | 桌面客户端 + iOS App（App Store：「鹅来面 - AI模拟面试&简历优化助手」） | 早期评测称不支持网页端 |
| 价格 | App Store 内购按面试时长：30 分钟 ¥68 / ¥108、120 分钟 ¥188、300 分钟 ¥378；基础功能免费 | 第三方说法不一，以购买页为准 |

## 二、实时助手大概是怎么实现的（推断）

和我们的「线上面试双路录音」是同一套架构，只是方向相反：

```
系统声音（会议软件里的面试官）──┐
                               ├─► 流式语音识别 ─► 判断“这是不是一个问题、问完了没有”
麦克风（候选人自己）───────────┘                       │
                                                      ▼
                           简历 + JD + 已经聊过的内容 ─► 大模型
                                                      │
                     先用快模型 1 秒出“回答思路”，再用强模型约 20 秒出“深度回答”
                                                      ▼
                                          悬浮窗 / 手机上显示给候选人看
```

- **声音来源**：系统声音（Windows 用系统回环录音，macOS 需屏幕录制权限或虚拟声卡）。系统声音 = 面试官，麦克风 = 候选人自己，靠分路天然区分说话人——和我们 1.2 之后的做法一样。
- **问题识别**：语音识别是流式的（边说边出字），再用规则或小模型判断一句话是不是提问、是否说完，触发生成。媒体实测也提到它会把候选人自己的话误认成面试官提问。
- **两段式生成**：1 秒出思路、20 秒出深度回答，基本可以确定是“快模型先给提纲 + 强模型再补全”，流式输出到界面。
- **延迟**：媒体实测“听到问题 → 生成 → 读出来”累计约 1.5~2 秒。

## 三、对我们（面试官这一侧）的启发

### 1. 候选人可能正在用这类工具——我们要能看出来

公开讨论里比较一致的信号（都只是参考，网络卡顿、紧张也会造成类似表现，不能单凭一条下结论）：

- **固定的停顿后给出过于完整的答案**：每题都停 2~5 秒，然后一口气说出结构工整、措辞书面的回答。
- **先逐字复述问题拖时间**：“您是问数据库的扩展性对吧……”。
- **追问就露馅**：用了自己解释不清的术语；被打断或换个角度问，细节对不上。
- **视线有规律地看向屏幕同一处**（读稿）。

我们已经有做这件事的数据：线上面试时两路录音带时间戳，能算出“面试官问完 → 候选人开口”的间隔。可以做：

- 报告里加「回答方式」一栏：每题的开口延迟、复述问题的次数、回答的书面程度，延迟异常一致或明显偏长时提示“建议追问细节确认”。
- 出题时多给“抗提词”的问法：问具体经历里的数字和取舍、让对方现场画数据流、打断后换条件追问（我们的「情景变更」「追问」本来就在做这件事，可以在面试中更突出）。

### 2. 把它的“实时助手”反过来用在面试官身上

| 它给候选人的 | 我们可以给面试官的 |
|---|---|
| 听出面试官问了什么 | **自动识别我问到了哪一题**：转写里出现准备好的题，自动标「已问」、当前题跳到下一题，不用手点 |
| 1 秒给出回答思路 | **候选人一答完，1~2 秒内提示**：这题的回答要点覆盖了哪几条（✓ / ✗）、建议追问一句什么 |
| 20 秒深度回答 | 每个项目问完，给一段小结：说清楚了什么、哪里含糊、要不要再深挖 |

### 3. 降低转写延迟

它是流式识别（边说边出字）；我们现在是“说完一句停 0.5 秒 → 整段上传识别”，一句话出来大约要 1.5~3 秒。面试官看转写不需要逐字实时，现在够用；如果要做上面的“实时提示”，可以改用支持 WebSocket 实时识别的服务（如讯飞、阿里云实时语音识别），把延迟降到 1 秒以内。

## 四、建议的下一步（按价值排序）

1. **面试中自动识别已问的题 + 候选人答完后的要点覆盖和追问建议**（面试官最直接受益）。
2. **报告里加「回答方式」分析**，提示可能在用 AI 提词的信号。
3. （需要时）换成流式语音识别，进一步降低延迟。
